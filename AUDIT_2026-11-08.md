# AI Tax — audit against the technical specification v2.0 (8 Nov 2026)

Checked: the spec (`AI_Tax_Technical_Specification_RU.docx`), the repository (commit `3992eac`), and the live site https://ai-tax-platform-mvp.vercel.app/.

**Verdict before the fix: not done properly.** The interface looked complete, but the core of the spec — correct numbers, real login, real payments, real document reading — was simulated. Most of it is now fixed in code (45 tests pass, production build passes). It is **not yet deployed**, and three things need your accounts (database, Stripe, admin password).

## Critical problems found (and what was done)

| # | Problem on the live site | Spec | Fix |
| --- | --- | --- | --- |
| 1 | **No login.** Every visitor opened the same account ("Alex Morgan") and its data. Anyone could act as any user by sending an `x-user-id` header. | §13, §17 | Real accounts (sign-up / sign-in / sign-out), scrypt-hashed passwords, signed HttpOnly session cookie; the header and plain cookie are ignored. "Try a demo" creates a private account with labelled sample data. |
| 2 | **Admin API had no access check at all** — anyone could list all users and documents, block users, mark refunds. Admin password `AdminTax2026!` was in the source code. | §14 | Admin role required on every call; admin account only from environment variables. |
| 3 | **Payments were fake.** Clicking "subscribe" or "buy export" made the server sign its own "webhook" and unlock the product — free exports for anyone. Stripe was never called. A seeded "verified" subscription existed. | §10, §17 | Stripe Checkout + webhooks verified by the Stripe SDK, idempotent, real refunds. Without keys the buttons say "payments not configured" and unlock nothing. |
| 4 | **2025 tax figures were out of date** (pre-July-2025 law): standard deduction $15,000 instead of $15,750, child tax credit $2,000 instead of $2,200, §179 $1.25M instead of $2.5M. **2026 figures were invented** (cited "Rev. Proc. 2025-42", which is not the 2026 procedure; every 2026 bracket, deduction and limit was wrong). | §7 | Re-entered from IRS sources: Rev. Proc. 2024-40, Rev. Proc. 2025-32 (incl. OBBBA changes), Notice 2026-10 / Announcement 2026-11 (2026 mileage 72.5¢, then 76¢ from 1 July). |
| 5 | **State tax was invented**: a flat "effective rate" (CA 6.5%, NY 6%…) applied to federal taxable income. | §2.2, §7 | Removed. No-income-tax states show $0; every other state shows "not calculated, not included". |
| 6 | **Headline savings were inflated.** The baseline left out all expenses, QBI, the child tax credit, etc., so the site showed "$18,462 confirmed real tax savings" before the user confirmed anything. Item savings = amount × a guessed marginal rate incl. the invented state rate. | §3.5, §3.6 | Baseline now includes everything that applies by law; savings are recalculated with and without each item. The demo now shows $2,518.67 confirmed (from the profile entries) and $6,854.75 more pending confirmation. |
| 7 | **Merchant name treated as proof**: "Staples", "WeWork", "CPA", "Google Ads" were marked "verified by document" from the bank line alone. | §2.3 | They are now "confirmation required" and generate interview questions. |
| 8 | **Credit logic wrong**: EITC used a made-up linear formula ignoring the number of children; refundable credits (EITC, additional CTC) were lost when tax was low; dependent-care credit was a flat 20%; education credits had no phase-out. | §3.3 | IRS EIC-table method, Schedule 8812 ACTC, §21 rate schedules for 2025 and 2026, AOTC/LLC phase-outs, refundable vs non-refundable split. |
| 9 | **Double counting**: fuel/repair costs on statements were deducted *and* standard mileage on top. Mileage counted as "confirmed" before the user confirmed a log. | §2.1, §3.4 | Fixed; mileage needs a confirmed log; §179 refused at ≤50% business use. |
| 10 | **PDFs and photos were not read.** A PDF's raw bytes were treated as text (real statements → 0 rows); images were labelled "OCR" but never OCR'd; the "OCR scan" sample was a text file renamed `.pdf`. | §2.1, §4 | Real PDF text extraction (pdf-parse) and OCR (tesseract.js); unreadable files are marked "needs review" and contribute nothing. Scanned PDFs: clear message, not read. |
| 11 | **No external AI at all**, while the status bar said "OpenAI API Live" whenever a key existed. | §11 | Status now says "rule-based (no external AI model connected)". Adding a real model is listed as open work. |
| 12 | **Data does not persist on Vercel**: the database lives in `/tmp` of each serverless instance — lost on restart, not shared between instances. Uploaded files likewise. | §11, §13 | Postgres support via `DATABASE_URL`; files now encrypted in the database; a warning banner shows while storage is temporary. |
| 13 | **Encryption/signing keys were constants in the public repo**, so "AES-256 encryption" protected nothing. | §13 | No constant keys; required with a real database. |
| 14 | **Second real user would crash**: question/recommendation IDs were not unique per user (found by the new tests). | — | IDs now include the user. |
| 15 | Copy promised outcomes ("Find every legal tax-saving opportunity", "Confirmed real tax savings", "VERIFIED"). | §15 | "Potential deductions", "estimated federal tax impact", "not a guarantee". |

Also: file content is now checked against its type, exact duplicate uploads are rejected, upload limit set to 4 MB (Vercel's body limit is 4.5 MB, the old 15 MB could never work), inputs validated, sign-in rate-limited, docs corrected (they claimed row-level security and "100% functional" webhooks that did not exist).

## What you need to do to make it live

1. **Database**: create a Postgres (Supabase or Neon free tier) and set `DATABASE_URL` in Vercel.
2. **Secrets**: set `SESSION_SECRET`, `FILE_SIGNING_SECRET`, `VAULT_ENCRYPTION_KEY` (each `openssl rand -hex 32`), and `ADMIN_EMAIL` / `ADMIN_PASSWORD`.
3. **Stripe**: `STRIPE_SECRET_KEY` + a webhook to `https://<domain>/api/stripe` → `STRIPE_WEBHOOK_SECRET` (events listed in ENVIRONMENT.md).
4. Push the branch so Vercel redeploys.
